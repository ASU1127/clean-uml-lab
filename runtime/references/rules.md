# 类图工程规则

本包支持 1–40 个 class/abstract/interface/enum 的类图子集、字段/操作文本、继承、实现、关联、依赖、组合和共享聚合。枚举只支持普通字面量名称；具体边界见 model.md。它不是完整 UML 校验器。

## 语义
- 泛化：子类指向父类，实线空心三角。
- 实现：实现类指向接口，虚线空心三角；不要把 extends 和 implements 混为一谈。
- 关联：没有导航性证据时用无箭头实线。导航性和业务流程方向不同。
- 枚举：保留 `«enumeration»` 及全部字面量，不能为了通过编译改称普通类。
- 依赖：依赖方指向被依赖方，虚线开放箭头。
- 组合：实心菱形位于整体端。先有整体/部分及生命周期依据，再选组合；不能仅凭字段或“拥有”推断。
- 共享聚合：不能因为对象可独立存在就自动选择空心菱形；语义不足时保留普通关联。
- 多重性：A 端的数值表示一个 B 对应多少个 A。只有明确约束才填；不明确时留空并在图外说明，不能擅自填 1。
- 缺少业务信息不应通过外观检查补全。不要生成用户未要求的 Repository、Controller、审计字段、方法或关系。
- 不为得到更好的布局分数删除节点、成员或关系。

## 纯净样式（项目默认偏好，不是 UML 强制标准）
白底黑线，统一字体；无阴影、渐变、彩色类图圆标、emoji、品牌、标题横幅、装饰边框、说明卡片、无意义图例。
保留必需的接口标记、可见性、关系、多重性和明确要求的约束。说明与警告放图外。
不强制正交线，不将任意交叉都判为规范错误；布局优劣需要阅读实验。
用户明确指定其他样式时以用户要求为准，研究对照中则冻结统一样式。
